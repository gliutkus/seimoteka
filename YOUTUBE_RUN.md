# Running the transcript harvest

The importer is implemented in `ingest/youtube.py`, with local Apple Silicon
speech recognition in `ingest/youtube_asr.py`. Results are staged in
`data/youtube/`; they are not yet loaded into Postgres or attributed to speakers.

Open `data/youtube/INDEX.md` for transcript links and coverage for every current
MP. `report.json` is the machine-readable snapshot. `run.json` records the
current phase, PID, and run status when using the full harvest command.

```bash
uv sync --group youtube --group asr
uv run --group youtube --group asr python -m ingest.youtube harvest --asr
```

Run from `files/`. Requires ffmpeg and Apple Silicon for the optional ASR phase.
The speech model is downloaded once into `data/youtube/models/`. ASR is local;
no paid transcription API or account cookies are used. The original public audio
is temporary and deleted after successful transcription, retaining its hash.

The full pass runs serially: refresh current MPs; search 20 results per MP;
enumerate OpTV's videos and streams archives; retrieve Lithuanian captions;
optionally transcribe publicly downloadable episodes lacking Lithuanian captions.
Search results are limited discovery, not an exhaustive index of YouTube.
Historical episodes involving people who are current MPs are included.

Rerunning skips completed searches and saved transcripts. A provider block stops
the caption phase and preserves the remaining queue. No proxy rotation, login
workaround, or paid/private-video access is attempted. Errors and absent captions
are distinct, and neither becomes an empty successful transcript.

For individual stages:

```bash
uv run --group youtube python -m ingest.youtube roster
uv run --group youtube python -m ingest.youtube discover --search-mps --results 20
uv run --group youtube python -m ingest.youtube discover --channel 'https://www.youtube.com/@OpTV_jusu_tiesa/videos'
uv run --group youtube python -m ingest.youtube captions --limit 100
uv run --group youtube python -m ingest.youtube captions --video VIDEO_ID
uv run --group youtube --group asr python -m ingest.youtube_asr --limit 1
uv run --group youtube python -m ingest.youtube report
```

`--refresh` repeats a discovery target. A larger `--results` value creates a new
search pass. `captions --retry` retries failed captions; successful transcripts
remain cached. `youtube_asr --retry` retries ASR failures. Run one network harvest
at a time; the full harvest command uses a process lock to prevent duplicate runs.
Individual stage commands are intended for use while the full harvest is stopped.

Transcript versions include original timestamped JSON, readable text, and WebVTT.
Locally generated versions also include model output, model revision, and audio
provenance. Automatic captions and ASR both need review, especially names,
numbers, negation, overlapping speech, and silence. Speaker IDs remain NULL.

The candidate matcher deliberately has high recall and may capture discussions
*about* MPs, unrelated people with similar surnames, clips, or parliamentary
speeches. The archive is a discovery and transcript staging area. It must not be
used as a verified corpus of podcast appearances without an appearance review.
No vote, misconduct, or speaker assertions are generated by this importer.

ASR downloads at most 250 MiB per episode and pauses if less than 5 GiB of disk
space remains. A missing/inaccessible audio source stays recorded as an error.
The Mac must remain awake and online for a running harvest to continue.

If public caption retrieval is blocked but public audio still works, continue
locally without repeatedly retrying captions:

```bash
REQUEST_DELAY=5 uv run --group youtube --group asr python -m ingest.youtube_asr --pending --limit 0
```

The current narrowed harvest scope is Remigijus Žemaitaitis only, MP ID `65703`:

```bash
REQUEST_DELAY=5 uv run --group youtube --group asr python -m ingest.youtube_asr --pending --limit 0 --mp-id 65703
```

This explicitly includes candidates whose captions are untested or blocked.
It does not label them as having no captions. Long episodes with full MP names
in the title are processed first, rotating across MPs; other candidates stay
in the queue. Priority does not verify an appearance. Known inaccessible videos
are skipped. Three consecutive audio/transcription errors pause the run.
The standalone ASR worker uses the shared harvest lock and updates `run.json`
with its PID, current video, download/transcription stage, and final status.

Additional local ASR lanes can run in parallel. They share a short queue-claim
lock, but each lane has its own process lock and status file. On the current
Mac, two lanes is the practical ceiling; three lanes caused memory pressure and
crashes. Run the main lane plus one extra lane:

```bash
REQUEST_DELAY=5 uv run --group youtube --group asr python -m ingest.youtube_asr --pending --limit 0 --lane 2
```

Lane `main` writes `run.json`; lane `2` writes `asr-2.run.json`. Claimed videos
are marked `asr_processing` so other lanes skip them. A stale claim becomes
eligible again after six hours, or immediately with `--retry`.

To add a paid Gemini lane that works from the back of the same queue while local
Whisper works from the front, set `GEMINI_API_KEY` or `GOOGLE_API_KEY` and run:

```bash
REQUEST_DELAY=5 uv run --group youtube --group gemini python -m ingest.youtube_gemini --pending --limit 0
```

Gemini uses `gemini.lock` and `gemini_run.json`, so it can run alongside the
local ASR worker. It temporarily marks a claimed video as `gemini_processing` so
the local worker skips it, then writes the same transcript artifacts with
`provider="gemini_transcribe"`. Audio is split into 29-minute chunks so word
timestamps stay within Gemini Transcribe limits. Gemini raw responses and
provenance are saved next to the transcript; temporary audio is deleted after
success. If Gemini fails, the candidate is returned to its previous queue status
and the failure is recorded in `gemini_status` / `gemini_error`.

Validation: `uv run --group youtube pytest -q` and `uv run ruff check .`.

## New videos after the harvest

The harvest stopped at 563 transcripts. New videos are found by
`uv run --group youtube python -m ingest.youtube_new run`, or the button
"Ieškoti naujų vaizdo įrašų" on the knowledge-base page: it searches again for
each MP, reads the pages of new videos into `descriptions/`, and adds those whose
title or description names an MP to `participants.json` (existing entries are
kept). They are transcribed only when prepared for review on the page.
